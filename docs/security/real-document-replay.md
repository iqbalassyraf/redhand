# Real-document replay: how the checks behave on real, long documents (recorded 2026-11-09)

**Why this exists.** The block gate (`docs/adr/0016-block-gate.md`, rule G5) found that none of our harmless test samples is longer than 824 characters, so nobody knew how
the checks behave on pages and documents. This record answers that with real documents nobody wrote for a benchmark. It is **not blind evidence and does not count for the
gate** (see Limits), but it is the first measurement on real long text.

**How it was made.** `scripts/radar_real_documents.py` (rules version below; command in the Re-run section). Every document is scanned as if a tool had returned it, by the same
`radar.scan_result` the gateway runs, reading at most 16 KiB from each end. Only paths and counts are recorded, never document text.

> **Update 2026-11-13 (M4.7b):** the rules changed after this record was made; the numbers below are history for the old rules. The new measurement, on
> a tuning set and a once-only frozen set, is in `docs/security/m4-7b-results.md`.

## What this tells us

1. **The script check flags every real web page.** All 10 built pages of our own dashboard (ordinary Next.js pages with `<script>` tags) raise a strong `RAD-OUT-001`. The check is
   right in principle (a script runs when a page is rendered) but a web-fetching agent never renders it, so blocking on this check would refuse almost every normal page. This is
   the concrete reason block mode stays off, and why the gate asks for long, realistic harmless samples before any check can qualify.
2. **On strangers' real documentation the hidden-instruction check flags about 1 in 8 and the risky-output check about 1 in 17.** The 186 third-party READMEs (117 npm packages, 69
   Python packages; 141 are 2 KiB or longer) were written by other people for other purposes. The most common reason is `RAD-INJ-005` ("tells the agent to run a command"): 13 of the 23
   hidden-instruction flags are READMEs with an `npm install && npm test` style instruction for a human developer. Sensitive-path mentions (`RAD-OUT-007`, 8) are next. The block gate asks
   for an upper bound of 3%; these are 17.9% and 10.3%.
3. **Our own repository is a poor sample and the numbers for it should not be quoted as typical.** A security product's docs and code are full of attack vocabulary (a third of the code files
   raise a hidden-instruction flag), so those rows are shown only for completeness.
4. **Nothing here is a detection rate.** Every document is treated as harmless, so a flag is a false alarm. How many real attacks the checks catch is measured only by the independent blind rounds
   (Coverage page).

## Limits

- Not independent and not blind: the repository's own text was written by the rule authors; the third-party READMEs are independent of them but are developer documentation, not the mix of helpdesk
  tickets, emails and pages a given customer's agents read. They do not count for the block gate.
- The numbers are specific to the packages installed on this machine on this date; re-running elsewhere gives different counts. The proof on the real staging gateway with DeepWiki
  (`scripts/radar_real_life_proof.py`, `docs/testing/briefs/2026-11-09-m4-6b-real-life-proof.md`) adds a second, larger sample of third-party documents.
- Every flagged document is counted as a false alarm, including one that might contain a real attack; no reviewer has opened the flagged files.
- The rules were not changed after seeing these results. Possible fixes (for example a lower confidence for shell install instructions in documentation, or for a full HTML page with ordinary
  scripts) would need a new blind round to measure and are listed in the follow-ups of the M4.6 report.

## Limits

- This repository's own documents and code were written by the team that wrote the rules, and a security product's text is full of attack vocabulary, so those rows are NOT typical. The third-party READMEs are strangers' real documentation and are the fairest row. None of this is blind evidence and none of it counts for the block gate.
- Security write-ups quote attacks on purpose, so flags there are expected. They are reported separately.
- Every flagged document is treated as harmless here, so a flag counts as a false alarm.
- The Radar reads at most 16 KiB from each end of a document, as the gateway does.
- The 95% upper bound is the same interval the block gate uses; with few documents in a group it is wide.
