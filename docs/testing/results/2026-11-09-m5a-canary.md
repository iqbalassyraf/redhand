- Agent `canary-test` is `revoked`. It was never frozen during the run.
- So done test 7 (a planted marker in a call is refused, alerted and recorded, with no freeze) is proven on staging for the **call** case.

**Not accepted as PASS:**
- **Step 13 (speed): NOT PASSED.** The run printed "OVER BUDGET: p99 is at most 250 ms but the budget is 50 ms". The stage that scans for honeytokens did not move (mean 0.009 ms before, 0.022 ms after), but 9 of 200 calls had to fetch context from core (2 before). That is unexplained: it may be Cloud Run cold start, or it may be linked to the canary. Needs a re-run, then a look at why.
- **Step 11 (glued value): inconclusive, not PASS.** The call was refused, so the documented limit was not shown. The value copied from the sentence ended with a full stop, so `${RH_CANARY}x` still held the value followed by a non-alphanumeric character. It needs a re-run with the 24 characters only.
- **Step 10 (one alert only): the number of alerts was not counted.** The database shows 4 trips as expected. The report says alerts were "rate-limited per policy" but gives no count of phone alerts.
- **Step 17 (roles): NOT RUN.** The reason given ("single admin account") is wrong. The operator and viewer accounts exist on staging since today, and the F1 brief uses them.
- **Step 12 (result case): NOT RUN** (optional).
- **Label:** the stored label is `system prompt canary` (lower case), not the preset's "System prompt canary". Harmless, but the owner typed or changed it.
